# Mobench 0.2 feature-parity checklist

This checklist maps the 0.2 parity handoff to the 0.2 implementation. The
comparison baseline is `v0.1.49` at
`13d716e3187bf4f0576276b738fd6d67a307e3c5`, including the native Android
reliability fixes merged in `d248badba78f9f6870b5fa79e2e0c00fd8d5d3a7`.

The isolated 0.2 worktree started from
`f3208946ca48f112e7279f2ba7b94f2303e4c3bb`, which matched
`origin/dcbuild3r/0.2`. The worktree already contained an unfinished
BrowserStack client extraction; that related work is being preserved and
completed before parity changes.

Status meanings:

- `present`: implemented on 0.2 and covered by focused evidence.
- `partial`: the 0.2 architecture has part of the behavior, but the handoff
  contract is not satisfied end to end.
- `missing`: no equivalent 0.2 behavior exists yet.
- `pending gate`: implementation may exist, but required downstream evidence
  has not passed on the final candidate SHA.
